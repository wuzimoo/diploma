## Назначение документа

Этот файл фиксирует все значимые изменения, которые были внесены в продукт после базовой реализации MVP. Документ можно использовать как источник для:

- обновления основной документации проекта;
- описания выполненных доработок в дипломной работе;
- подготовки changelog / release notes;
- синхронизации README, модульной документации и пояснения по деплою.

## 1. Общий итог доработок

В систему были внесены изменения по нескольким крупным направлениям:

1. Доработана предметная модель строительной компании:
   - добавлены бригады;
   - добавлен состав бригад;
   - добавлен план работ по объектам;
   - расширена детализация строительных объектов.

2. Улучшены рабочие сценарии для ролей:
   - worker больше работает с закрепленным объектом и бригадой;
   - admin/foreman получили более полный интерфейс управления сотрудниками, бригадами, объектами и отчетами.

3. Существенно улучшен пользовательский интерфейс:
   - добавлены модальные формы редактирования;
   - добавлены toast-уведомления;
   - улучшена адаптивность;
   - исправлены проблемные макеты карточек и секций.

4. Обновлена инфраструктура тестирования:
   - Playwright e2e переведен на стабильный preview-server сценарий;
   - проверены базовые пользовательские маршруты admin и worker.

5. Выполнено продуктовое переименование:
   - из `Roman's ERP` в `Builder ERP` / `Билдер ERP` в пользовательских точках интерфейса и метаданных.

### 2.5. Ограничение на активное членство в нескольких бригадах

Исправлена важная бизнес-логика:

- теперь один сотрудник не может одновременно быть закреплен в нескольких активных бригадах;
- при попытке добавить сотрудника в другую активную бригаду backend возвращает конфликт;
- на frontend поверх этого добавлен сценарий переноса между бригадами с подтверждением.

Это соответствует реальному операционному процессу в строительной компании, где сотрудник не должен числиться активным участником нескольких текущих бригад одновременно.

### 2.6. CORS и деплой-совместимость

Backend был доработан для корректной работы с Vercel deployment domains:

- добавлена поддержка `*.vercel.app` через regex-настройку CORS;
- устранены проблемы логина с preview/prod deployment URL.

Связанные файлы:

- `backend/app/main.py`
- `backend/app/core/config.py`

### 5.2. Стабилизация тестового стенда

Изначально e2e использовали `vite dev server`, что давало нестабильные переходы в sandbox/CI-режиме.

Сделано:

- Playwright переведен на `vite preview`;
- добавлен отдельный script:
  - `preview:e2e`;
- e2e теперь запускаются через готовый production build.

Преимущества:

- стабильнее навигация;
- меньше флапа в CI;
- ближе к реальному production-поведению.

## 8. Что остается вне этого документа

В рамках этой волны работ сознательно не закрывался отдельный security-этап.

То есть вне текущего продукта остаются задачи следующего этапа:

- жесткая role isolation;
- донастройка прав доступа на backend;
- дополнительная фильтрация API-ответов по ролям;
- более строгие ограничения на доступ worker/foreman к данным.

Также отложены более тяжелые product-задачи:

- полноценный файловый storage для медиа;
- расширенный CRUD календаря как планировщика;
- отдельный audit log действий пользователей.
